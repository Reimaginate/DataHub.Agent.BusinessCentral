# DataHub Agent for Business Central 1.0.0-beta.1

This is the first public beta of the Reimaginate DataHub Agent for Microsoft
Dynamics 365 Business Central.

## Packages

- `Reimaginate.DataHub.Agent.BusinessCentral.Abstractions`
- `Reimaginate.DataHub.Agent.BusinessCentral`
- `Reimaginate.DataHub.Agent.TestFramework.BusinessCentral`

All three packages are versioned and released together.

## Highlights

- Standard Business Central v2.0 OData routing with configurable API routes.
- Bidirectional explicit and scheduled merge/sync processing, markers,
  pagination, exact-ETag writes, bounded transient retry and fail-closed
  ambiguous-create handling.
- Parent-scoped document-line routing and reference resolution.
- Scenario Builder test helpers plus deterministic fault-injection support.
- An optional AL extension that adds server-enforced correlation reservations
  for sales and purchase orders and their item lines.
- A representative public implementation for Customer, Item and Sales Order
  integrations.

The private validation suite covers customers, contacts, items, vendors,
reference data, sales and purchase documents, posted transaction snapshots,
journals, payments, dimensions and ledger records. Concrete Data Hub and
Business Central models remain implementation-owned rather than part of the
runtime contract package.

## Setup and security

Use a single-tenant Entra application with Business Central
`API.ReadWrite.All`, company-scoped Business Central permission sets and no
`SUPER` assignment. Grant only the document, reference-data or ledger access
needed by the selected integrations. Store credentials in managed identity,
workload identity, environment configuration or a secret store; never commit
them.

The optional correlation extension is separately deployed to Business Central
and enabled through `CorrelationReservationsEnabled`. A failed reservation
never silently falls back to an uncorrelated create.

## Beta limitations

- Public APIs and configuration may change before version 1.0.
- Customer-specific models and mappings must be supplied by the consuming
  implementation; the public sample is illustrative rather than canonical.
- Some standard Business Central resources do not expose a server-enforced
  create key. Ambiguous writes without correlation fail for reconciliation
  instead of being retried unsafely.
- Standard document-line APIs do not provide independent incremental markers;
  consumers must reconcile children through their parent workflow.
- Financial-document lifecycle actions are outside the default agent flow. The
  agent does not automatically post, release, ship, receive, invoice, cancel or
  correct documents.

See the repository README and the correlation-extension README for detailed
configuration and deployment guidance.
