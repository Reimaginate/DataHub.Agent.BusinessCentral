# DataHub Agent for Business Central 1.0.0-beta.2

This beta makes the public reference implementation a copyable starting point
for connecting a Business Central agent to an existing DataHub deployment.

## Packages

- `Reimaginate.DataHub.Agent.BusinessCentral.Abstractions`
- `Reimaginate.DataHub.Agent.BusinessCentral`
- `Reimaginate.DataHub.Agent.TestFramework.BusinessCentral`

All three packages are versioned and released together.

## Highlights

- Replaces source-project references in the public sample with the published
  Business Central runtime and test-framework packages.
- Adds complete registrations for Account/Customer, Product/Item, Sales Order
  and Sales Order Line pairs, including mapper and mediator handlers.
- Adds configuration examples for shared-key, application-registration and
  managed-identity DataHub authentication, plus `DefaultAzureCredential` for
  Business Central.
- Adds configuration validation, a credential-free validation command, a
  read-only connectivity smoke test, explicit merge/sync commands, a
  dependency-ordered one-shot processor and a long-running worker.
- Adds fail-closed write and production-environment gates, scheduled-processing
  controls, Docker deployment files and an expanded copy/configure/deploy guide.
- Expands deterministic sample coverage for configuration, registration,
  mapping, routing, parent-child processing, retry and ETag conflict handling.
- Fixes runtime configuration binding so root-level `DataHubClientOptions` are
  retained when Business Central agent settings are bound from a named section.

## Upgrade notes

Update all three Business Central package references to `1.0.0-beta.2`. Copy
the refreshed sample into the consuming solution, replace its example models
and mappings with implementation-owned equivalents, and keep write execution
disabled until validation and read-only smoke checks pass.

## Beta limitations

- Public APIs and configuration may still change before version 1.0.
- The sample models and mappings are examples, not a canonical business schema.
- Ambiguous creates without a server-enforced correlation reservation fail for
  reconciliation rather than being retried unsafely.
- Standard document-line APIs do not provide independent incremental markers;
  children must be reconciled through their parent workflow.
- The agent does not automatically post, release, ship, receive, invoice,
  cancel or correct financial documents.

See the repository README and the optional correlation-extension README for
configuration, security and deployment guidance.
